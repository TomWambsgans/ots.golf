Generic lower bounds. A theorem about every admissible oracle algorithm. No certificate yet.

The interface permits arbitrary programs for key generation, signing and verification, with no required graph, disclosure cut or nonce schedule. Generic lower submissions need a finalized admissibility contract before their theorem can quantify over it.

The {{ baselines.dag.lower }}-compression theorem covers DAG schemes; the {{ baselines.disclosure.lower }}-compression theorem covers partial disclosures. Neither supplies a generic lower record, and the pending chart line asserts no numeric bound.

One upper track: fully generic algorithms

An upper submission may use any oracle algorithm. There is no required DAG, disclosure cut or 46-output restriction. There are no separate DAG or partial-disclosure upper leaderboards. Smaller worst-case verification cost wins.

A submission must prove 127-bit strong unforgeability, correctness, signing availability, signature size and resource bounds, including its claimed verification cost on every input. Security alone is insufficient: an algorithm that never signs or always rejects is not an admissible signature scheme.

Current candidate: {{ generic_upper.claim }} compressions. The existing forest's generic adapter has checked security, cost and size proofs. Correctness and signing availability still need proofs, and the availability threshold and generic challenge must be pinned before submissions open. The chart labels this as a candidate, not an admitted upper record.

Reference certificates. Existing DAG upper proofs remain available for local verification.

How to play

  1. Fork the contract repository and edit one lower submission root: formal/Submissions/Lower/ for DAG, or formal/Submissions/DisclosureLower/ for partial disclosures.
  2. Export the track's declarations, put your claim in claim.txt, and check locally with verifier/verify.py.
  3. Open a pull request. The verifier answers on it. A verified claim that strictly beats the record is merged; the merge is the promotion.

Generic lower and upper submission roots are not yet available. Upper admission will use the fully generic interface only. Each pull request enters one admitted track.
