Rules

How cheaply can a hash-based one-time signature be verified?

An upper bound constructs a scheme that never exceeds the claimed cost. A lower bound proves that every admissible scheme in a chosen class has worst-case cost at least as large. Every claim needs a Lean-kernel-checked proof.

{% include "_how.html" %}

Three lower-bound frameworks

Each class has its own lower record. A restricted result does not establish the same bound for a broader class.

1. Generic algorithms

Arbitrary terminating oracle programs for key generation, signing and verification. No required graph, disclosure pattern or nonce format. Honest signatures must verify, and signing must succeed with probability at least 1/2 for every message-selection rule based on the public key. This availability threshold is fixed for generic lower submissions.

2. DAGs

A fixed, public, directed acyclic graph of secret random sources, deterministic operations and hashes, with unrestricted sharing. The public key is the low 128 bits of its root hash. A signature reveals a cut: node values meeting every source-to-root path, excluding the root. Verification reconstructs the root forwards.

{% include "_rules_cut_diagram.html" %}

3. Partial disclosures

DAGs with at most 46 distinct hash origins per signature payload. Trace disclosed values backwards through deterministic nodes, stopping at hashes; count distinct hash nodes reached. Sources count zero; every declared parent edge counts.

Several disclosed values derived from the same hash node count once across the whole payload. Two hash nodes count twice, even if their values are equal. Hashing starts a new origin; earlier hashes behind it are not counted.

Generic admissibility. Representation, correctness, availability and cost.

The scheme supplies an injective bit-string encoding of its signatures: different signatures must have different encodings. Every signature the signer can return fits in 5,504 bits; the verifier always rejects oversized encodings.

Honest signing and verification share the same oracle. A returned signature is rejected with probability zero. For each message-selection rule based on the public key, signing succeeds with probability at least 1/2, averaged over honest key generation and signing. This is not a per-key guarantee or an availability guarantee after adversarial oracle queries.

Key generation, signing and verification obey their cost bounds on every execution path. Signing is bounded for every secret key and message; verification for every public key, message and signature, including rejection. A lower claim rules out every smaller such verification budget. Private randomness and adaptive oracle queries are permitted.

Exact DAG model. Fixed dependencies; stored values; forward evaluation.

The finite graph, node lengths and deterministic functions are public and fixed. Sources are independent uniform bit strings of arbitrary fixed lengths. A deterministic node uses only its declared parents; a hash node hashes one parent's entire bit string. Concatenation or encoding is a deterministic operation. Parents precede children, and sharing is unrestricted.

Key generation evaluates every node once and stores all values as the secret key. Signing reveals stored values. To reconstruct, walk backwards from the root along every declared parent edge, stopping at disclosed nodes; then evaluate the required nodes forwards, once each. No undisclosed source may remain on a required path, and the root itself cannot be disclosed.

DAG signature format. A message-and-nonce hash selects the cut.

The scheme supplies 2115 indexed cuts; cuts may repeat. Read the low 128 bits of H(message ‖ nonce) as an integer; it is valid when below 2115. Signing tries up to 221 uniformly sampled 256-bit nonces without replacement and stops at the first valid index, otherwise it fails.

The signature contains the nonce followed by the cut's node values, in node order, totaling at most 5,248 payload bits. Verification rejects an invalid index or a payload of the wrong length. Otherwise it reconstructs the root and compares its low 128 bits with the public key.

Verification costs one compression for the message-and-nonce query plus the costs of all reconstructed hash nodes. The score is the maximum over every indexed cut, even a cut that is unlikely to be selected.

Encoded disclosures. Encoding does not replace the cut requirement.

A Reed–Solomon encoder can be a public deterministic node. Coordinate nodes derived from one digest have one hash origin; a coordinate depending on two digest nodes has two. Count every declared dependency, even if the function ignores it.

The disclosed coordinate nodes must still form a valid cut. Verification follows the declared graph: being able to recover an omitted value mathematically does not replace that requirement. A decoder is permitted as a downstream deterministic node whose parents supply its inputs.

One upper track: generic algorithms

Submit any oracle algorithm. Prove that honest signatures verify, signing succeeds with the required probability, and security, size and resource bounds hold. The claimed verification cost must cover every input and execution path, including rejection. There is no DAG or disclosure restriction.

How to submit

Open: generic lower, DAG lower and partial-disclosure lower. Pending: generic upper, until its admissibility requirements and signing-failure allowance are pinned.

  1. Fork the repository. Change only formal/Submissions/GenericLower/, formal/Submissions/Lower/ or formal/Submissions/DisclosureLower/.
  2. Put your integer claim in claim.txt and export the required declarations from Solution.lean. Follow the exact submission requirements.
  3. Run python3 verifier/verify.py lower --source . (or generic-lower or disclosure-lower), then open a pull request. A verified strict improvement is merged and becomes the record.

No sorry or extra axioms: only {{ cfg.permitted_axioms|join(', ')|safe }}. Verification has {{ cfg.limits.wall_clock_seconds // 60 }} minutes and {{ cfg.limits.memory_bytes // 1073741824 }} GiB. The generic interface, generic lower statement, DAG contract, disclosure condition and verifier configuration define the exact requirements.

Legacy DAG upper certificates remain available as references. Their submission roots are closed.

Submission format. Files, imports and the pinned toolchain.

Use one flat root: identifier-named .lean files, claim.txt, and an optional README.md. Solution.lean is required. The claim is a non-negative integer without leading zeros, at most {{ cfg.limits.max_claim|int }}, with at most one trailing newline. The verifier inserts it into the exact theorem statement.

Import only Mathlib, VCVio, your track's permitted contract modules and sibling files. Protected definitions cannot be changed by a submission. Use the pinned Lean toolchain and dependency manifest. Limits: {{ cfg.limits.max_files }} files, {{ cfg.limits.max_file_bytes // 1048576 }} MiB per file and {{ cfg.limits.max_total_bytes // 1048576 }} MiB total. Verification runs without network access.

native_decide introduces an unpermitted axiom. The exported declarations must match the rendered challenge exactly; a numerical search alone is not a proof. See the full submission specification.
