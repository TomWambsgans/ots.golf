{# Competition-specific oracle, cost and security rules. #}

What are the hash and cost rules?

All parties share one random oracle: each new input bit string gets an independent uniform 256-bit answer; repeated inputs get the same answer. There are no implicit labels or domain separation. Hashing is the only cryptographic primitive.

A compression costs one unit per started 512-bit input block, with a minimum of one, even for empty or repeated queries. Explicit distinguishing bits count as input. Deterministic computation and randomness are free, including for the attacker. Every cost bound is worst-case over all execution paths.

What does 127-bit security mean here?

The attacker sees the public key, may query the oracle, requests one chosen-message signature, then attempts a forgery. For every budget B covering the whole experiment on every run, success must be strictly below B / 2127. Include key generation, signing, the attacker's queries and final verification.

Upper bounds require strong unforgeability: any accepted pair different from the signed pair counts. Lower bounds count only accepted forgeries on an unsigned message. If signing fails, any accepted pair counts in either experiment.
