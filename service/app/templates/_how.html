{# Competition-specific oracle, cost and security rules. #}

What are the hash and cost rules?

All parties share one random oracle on bit strings. Each distinct input gets an independent uniform 256-bit answer, shared across all uses. Hashing is the only cryptographic primitive.

A hash query costs one compression per started 512-bit input block, with a minimum of one. Every call is charged, including repeated queries. Input lengths include explicit parameters and tweaks. Deterministic computation and randomness are free for all parties. Every cost bound is worst-case over all execution paths.

As Justin Drake observed, a block-based implementation can pad a per-key public parameter to a full block, absorb it once, and reuse the resulting hash state. This makes the parameter a shared setup cost. The model therefore charges each query for its explicit input bits.

What does 127-bit security mean here?

The attacker sees the public key, may query the oracle, requests one chosen-message signature, then attempts a forgery. For every budget B covering the whole experiment on every run, success must be strictly below B / 2127. Include key generation, signing, the attacker's queries and final verification.

Upper bounds require strong unforgeability: any accepted pair different from the signed pair counts. Lower bounds count only accepted forgeries on an unsigned message. If signing fails, any accepted pair counts in either experiment.
