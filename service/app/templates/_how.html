How does the hash oracle work?

A random oracle is an idealized hash function. Give it a bit string it has never seen, and it returns an independent, uniformly random 256-bit answer. Ask again with the same input, and it returns the same answer.

Every party uses this one oracle, including the attacker. It has no built-in labels or domain separation: equal inputs receive equal answers, even when used for different purposes. A scheme may add distinguishing bits to its inputs, but pays for those bits.

What does one unit of cost mean?

One unit is a compression: processing a started 512-bit input block. Hashing up to 512 bits costs one; hashing 513 bits costs two. Every query costs at least one, even if its input is empty or has already been queried.

Count the complete input, including any distinguishing bits. Deterministic computation and randomness are free for every party, including the attacker. Cost bounds are worst-case over every execution path, not averages over typical runs.

What does 127-bit security mean here?

The attacker sees the public key, may query the oracle, requests one signature on a chosen message, then attempts a forgery. Security bounds the probability that the verifier accepts it.

If the whole experiment costs at most B compressions on every run, forgery success must have probability strictly below B / 2127. This budget includes key generation, signing, the attacker's queries and final verification.

Upper bounds require strong unforgeability: any accepted message/signature pair different from the signed pair counts as a forgery. Lower bounds assume the weaker requirement that only forgeries on an unsigned message count. If signing fails, any accepted pair counts in either experiment.
