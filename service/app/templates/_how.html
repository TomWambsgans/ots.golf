1. What is a one-time signature?

A signature scheme is three algorithms. Key generation produces a secret key sk and a public key pk. Signing takes sk and a message m and returns a signature σ. Verification takes pk, m and σ and accepts or rejects. The scheme is one-time when a key signs a single message: an attacker who sees pk and one signature, on a message of its choice, must not be able to produce any other pair that verifies.

One-time signatures are the building block of hash-based signatures. XMSS, SPHINCS+ and their descendants, including leanVM's signature shown on the home page, sign many messages by placing many one-time keys under a Merkle tree. Every verification pays for the one-time part, in a hardware wallet, in a blockchain client or in a SNARK that aggregates thousands of signatures. Its cost is the number worth minimizing.

A hash-based one-time signature uses nothing but a hash function. Lamport's scheme has two secrets per message bit; the public key is the hash of all their hashes, and signing reveals one secret per bit. Winternitz's scheme replaces each pair by a chain of hashes and reveals the value at the position given by the message digit; the verifier hashes the rest of the way up. Both follow the same pattern: key generation runs a fixed computation on secret random inputs, a signature reveals some intermediate values, and the verifier recomputes the final hash and compares it with the public key.

2. The hash function: a random oracle with a price

The only cryptographic tool is a hash function H, modelled as a random oracle. A query is a public label τ and an input u. Every new pair (τ, u) gets an independent, uniformly random 256-bit answer; asking again returns the same answer. Labels keep the roles of the hash apart: each hash node of a scheme has its own label, and the label enc is reserved for hashing the message. Signer, verifier and attacker can evaluate H only by querying it. A query on input u costs

c(u) = ⌈ (|u| + 192) / 512 ⌉ compressions.

Why blocks. A hash function absorbs its input in fixed-size blocks, and each block is one call of its compression function; SHA-256's blocks are 512 bits. That call is the unit of work in software, in hardware and in a SNARK circuit, so counting compressions is counting what the verifier pays. Charging per started block means that a short input costs one compression and a long input costs proportionally more: a scheme cannot hide work in one enormous hash.

Why 192 extra bits. Deployed tweakable hash functions never hash a bare value. They prepend a 128-bit public parameter, different for every key pair, so that one precomputation cannot attack all users at once, and a 64-bit tweak, the address of the position in the scheme, so that no two positions hash alike. These 192 bits occupy part of the first block, and the model charges for them. It does not need to represent them: its labels play the tweak's role for free. So a chain step over a 128-bit value hashes 320 bits and costs one compression, the index query over a 256-bit message and a 256-bit nonce hashes 704 bits and costs two, and the root of the record scheme, over 41 chain ends of 128 bits, costs eleven.

Everything else is free. Concatenating, splitting, truncating, comparing, drawing randomness, storing values: none of it counts, for anyone. Only queries to H cost, and nothing else bounds the attacker's computation. That keeps the cost measure simple and makes the lower bound stronger.

3. The shape of a scheme: a graph of hashes

A scheme is a fixed, public, finite directed acyclic graph. An edge from v to w means that w uses the value of v. Every node has a fixed output length. There are three kinds of nodes.

  • Secret sources have no parents. Each holds an independent, uniformly random string.
  • Deterministic nodes apply a public function to their parents' values: concatenate, select bits, truncate, anything computable without H. They cost nothing.
  • Hash nodes have one parent and their own label. Their value is H(label, parent value), 256 bits, and evaluating one costs c of the parent's value.

One hash node has no children: the root. Every node has a path to it. Key generation samples the sources, evaluates the graph in topological order and publishes the first 128 bits of the root as the public key; the secret key is the whole table of values. Key generation may cost at most 1024 compressions. The graph, its functions, lengths and labels are chosen once, independently of the oracle, and are public.

Lamport, Winternitz, forests of chains, trees over concatenations: every hash-based one-time signature in the literature is such a graph, and so is any scheme whose signatures consist of node values selected by hashing the message.

4. Signing reveals a cut

Besides the graph, a scheme fixes M = 2115 disclosure sets A0, …, AM−1. Each is a set of nodes that excludes the root and meets every path from a secret source to the root: a cut. Excluding the root forces the verifier to recompute it; meeting every path guarantees that the revealed values suffice to do so.

To sign m, the signer draws a 256-bit nonce η and reads the index i from the first 128 bits of H(enc, m ‖ η). If i ≥ M it draws another nonce, up to 221 times; one nonce in 213 works, so failure is negligible. The signature is η followed by the values of the nodes of Ai in a fixed order. Lengths and order are known, so there are no node identifiers and no delimiters. Writing ℓi for the total length of the values on Ai, a signature has 256 + ℓi bits, and the model requires ℓi ≤ 5248: signatures of at most 5504 bits. The message decides which values are revealed; the signer computes nothing new.

5. Verification, and the number we measure

The verifier recomputes i from m and η, two compressions, and rejects if i ≥ M or if the revealed string does not have length ℓi. It splits the string into the values of Ai, walks back from the root, stopping at the nodes of Ai, evaluates the visited nodes in topological order, and accepts if the first 128 bits of the recomputed root equal pk. With Ei the set of hash nodes it evaluates, verifying a signature of index i costs

Ci = 2 + Σg ∈ Ei cg compressions,

and the score of a scheme is maxi Ci, the cost of its most expensive signature. In the figure above, four hash nodes are recomputed for 2 + 2 + 1 + 1 compressions, so that signature verifies in 8. In the record scheme, 41 chains of 20 hashed together into the root, every signature recomputes 96 chain hashes and the 11-compression root: 2 + 96 + 11 = 109.

6. Security: one signature, then a forgery

The attacker receives pk, may query H at will, asks for one signature on a message of its choice, and outputs a message–signature pair. It wins if the verifier accepts the pair and it differs from the one it received. Let B bound the compressions spent in the whole experiment, key generation, signing and the final verification included. The scheme is secure when every attacker wins with probability below B / 2127: a forgery costs about 2127 compressions per unit of success probability. This is the predicate Scheme.Secure of the statement.

7. Two tracks, one number

Between the two records lies the answer: the least worst-case verification cost of a secure scheme with these parameters. The upper track approaches it from above: submit a scheme, a proof that it is secure and a proof that every signature verifies within the claimed cost; smaller claims win. The lower track approaches it from below: prove that every secure scheme has a signature at least that expensive; larger claims win. Both are Lean theorems about the same pinned statement, formal/OptimalOTS/Statement.lean, checked by the kernel.
