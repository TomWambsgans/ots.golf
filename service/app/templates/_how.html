How it works

1. A signature scheme is a public computation on secret inputs

A scheme is a fixed directed acyclic graph. Its leaves are secret sources, uniformly random bit strings. The other nodes are either hash nodes, which query a random oracle H on their single parent's value, or deterministic nodes, which apply any public function to their parents (concatenate, truncate, split; these are free). One hash node is the root. Key generation draws the sources, evaluates the graph, and publishes the first 128 bits of the root as the public key.

2. Signing reveals a cut

The scheme also fixes 2115 disclosure sets A0, …, AM−1: sets of nodes, never the root, meeting every path from a source to the root. To sign a message m, the signer draws a nonce η, reads the index i as the first 128 bits of H(m ‖ η) (trying another nonce if i ≥ M), and outputs η together with the values of the nodes of Ai. The message chooses which values are revealed; the signer never computes anything new.

3. Verification recomputes the root, and its cost is what we measure

The verifier recomputes i from m and η, checks the length of the revealed string, evaluates every node above the cut from the revealed values, and accepts if the first 128 bits of the root equal the public key. Every query to H is charged one compression per started 512-bit block of input; everything else is free. The score of a scheme is the cost of its most expensive signature, index query included.

4. Security: one signature, then a forgery

The attacker receives the public key, may query H freely, and asks for one signature on a message of its choice. It wins if the verifier then accepts a message–signature pair different from the one it received. Counting the compressions of the whole experiment (key generation, signing, the attacker's queries, the final verification) as B, a scheme is secure when every attacker wins with probability below B / 2127: a forgery costs about 2127 compressions per unit of success probability.

5. Two games, one number

Somewhere between the records lies the true optimum: the cheapest worst-case verification any secure scheme with a 128-bit public key and signatures of at most 5504 bits can have. The upper track attacks it from above: exhibit a scheme, prove it secure, and bound the cost of every signature. The lower track attacks it from below: prove that every secure scheme has a signature at least that expensive. Both certificates are Lean theorems about the same statement, formal/OptimalOTS/Statement.lean, checked by the kernel.
