One-time signatures. A key signs a single message. Seeing the public key and one signature, nobody should be able to produce another pair that verifies.

A signature scheme is three algorithms. Key generation makes a secret key sk and a public key pk. Signing turns sk and a message m into a signature σ. Verification accepts or rejects (pk, m, σ).

One-time signatures are the building block of hash-based signatures such as XMSS and SPHINCS+: a Merkle tree holds many one-time keys, and every verification pays for the one-time part. That cost is what this competition minimises.

A hash-based one-time signature uses nothing but a hash function. Lamport hashes secret strings and reveals one per message bit; Winternitz replaces the secrets of a group of message bits by one hash chain and reveals the value at the position the message dictates. Both follow one pattern: key generation runs a fixed computation on secret random inputs, a signature reveals a few intermediate values, and the verifier recomputes the final hash and compares it with the public key.

One tool, one price. The only cryptography is a hash function, a random oracle. A query costs one compression per started 512-bit block of its input. Everything else is free.

Each previously unqueried bit string receives an independent uniform 256-bit answer. Repeating the same string receives the same answer, including across node and index queries. Signer, verifier and attacker learn H only by querying it. A query on an input u costs

c(u) = ⌈ |u| / 512 ⌉ compressions, and at least one.

The oracle takes only an input string, with its length. It supplies no labels, tweaks or domain separation. A scheme can construct a tweak inside an input using deterministic nodes, and those bits count towards the input length and cost.

The upper baseline prepends a 16-bit tweak to every node query. Its chain inputs are 144 bits and its three-digest inputs are 400 bits, each costing one compression. Its root input is 912 bits and costs two. The message-and-nonce index has 512 bits and costs one. Concatenating, splitting, comparing and drawing randomness cost nothing, and the attacker's other computation is unbounded.

A scheme is a graph. Secret random sources, free deterministic nodes of any shape, and hash nodes. The low 128 bits of the root hash are the public key.

The graph is fixed, public, finite, directed and acyclic. Each node holds a bit string of a fixed length, computed from its parents' values, and is one of three kinds.

  • Secret sources have no parents and hold uniformly random strings, of any length.
  • Deterministic nodes apply any public function to any number of parents and produce any length: concatenate, select bits, split, combine, look up a table, anything computable without H. They cost nothing.
  • Hash nodes have one parent. Their value is H(parent), 256 bits, at cost c of the parent's length. The parent may be a concatenation of many values, so a hash node absorbs inputs of any size, at a price.

A value may feed any number of nodes. One hash node is designated the root. Key generation samples the sources, evaluates the graph in order, within 1024 compressions, keeps every value as the secret key, and publishes the low 128 bits of the root as pk.

Lamport, Winternitz, chains under trees: the hash-based one-time signatures of the literature are such graphs, and so is anything else built from a hash function whose signatures consist of node values.

A signature is a cut. Hashing the message with a nonce selects one of 2115 disclosure sets. The signature is the nonce and the values of that set, at most 5504 bits.

A scheme fixes M = 2115 disclosure sets A0, …, AM−1. Each is a cut: a set of nodes that excludes the root and meets every path from a secret source to the root. To sign m, the signer draws a 256-bit nonce η, reads the index i from the low 128 bits of H(m ‖ η), and tries fresh nonces until i < M, for at most 221 trials, after which signing fails. A previously unqueried input lands below M with probability 2−13. The signature is η followed by the values of Ai in a fixed order: at most 5248 bits of values. The message chooses what is revealed; the signer computes nothing new.

The score. The verifier recomputes the root from the revealed values. A scheme scores the cost of its most expensive signature.

The verifier recomputes i from m and η, one compression, rejects if i ≥ M or if the revealed string has the wrong length, splits it into the values of Ai, evaluates every node between the cut and the root, and accepts if the low 128 bits of the recomputed root equal pk. With Ei the hash nodes it evaluates, the signature of index i costs

Ci = 1 + Σg ∈ Ei cg compressions,

and the score is maxi Ci. The signature in the figure of the cut costs 1 + 8 = 9. In the baseline scheme, 63 chains of length 14 grouped by three into 21 digests, those by three into 7, and the 7 hashed into the root, every signature recomputes 103 chain and digest hashes and the two-compression root: 1 + 103 + 2 = 106.

Partial disclosures. Reveal any pieces of seeds or of at most 46 hash outputs. The payload still fits in 5,248 bits, plus the 256-bit nonce.

This framework adds one condition to the DAG model. Trace each disclosed node backwards through deterministic operations, stopping at the first hash on each path. Across the whole payload, at most 46 distinct hash nodes may be reached. Secret sources contribute no hash origin; a new hash replaces its inputs' origins with its own.

Arbitrary fragments and deterministic encodings are allowed. If d = H(seed) and c = ReedSolomon(d), revealing any chosen symbols of c, including parity symbols, counts one origin. Several slices of that digest still count once. Mixing two digests counts two origins, even if the encoded result is short. Every parent edge of a deterministic node counts when tracing origins, even if its function ignores that parent.

The disclosure sets must still cut every secret-source-to-root path, and verification reconstructs the graph forwards from the disclosed nodes. The rule allows encodings expressible in that model; it does not add arbitrary decoding from a chosen subset of symbols.

An upper submission proves both 127-bit security and the 46-origin condition. A lower submission proves its bound for every weakly secure DAG scheme satisfying that condition. Its bound does not change the unrestricted DAG record.

Security. One signature on a message of the attacker's choice, then a forgery. An attacker spending B compressions must win with probability below B / 2127.

The attacker receives pk, queries H at will, asks for one signature, and outputs a message and a signature. It wins if the pair verifies and differs from the one it received. B bounds the compressions spent in the whole experiment on every run, key generation, signing and the final verification included. This is Scheme.Secure in the statement, strong unforgeability. The weak form, Scheme.WeaklySecure, counts only forgeries on a message other than the signed one; every secure scheme is weakly secure.

Two tracks per active framework. Upper: a scheme with Lean proofs of its security and its score; smaller wins. Lower: a Lean proof that no secure scheme scores less; larger wins.

Between the two records lies the answer: the least worst-case verification cost of a secure scheme with these parameters. An upper-track certificate is a scheme, a proof that it is secure, and a proof that every signature verifies within the claimed cost. A lower-track certificate proves that every weakly secure scheme, and so every secure one, has a signature at least that expensive. Both are theorems about the same pinned contract, checked by the Lean kernel. The partial-disclosure framework additionally uses formal/OptimalOTS/Disclosure.lean to restrict the scheme class.

The unrestricted DAG baselines are 18 compressions for the lower track and 106 for the upper track. The lower proof shows that cheaper verification would force many indices to recompute the same hash nodes, letting an attacker convert a signature and forge on a different message. A stronger bound in the partial-disclosure class does not improve the unrestricted DAG bound.
